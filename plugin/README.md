# Плагин Brim для STE Slicer

Плагин добавляет в STE Slicer окно чата. Пользователь описывает задачу и прикладывает файлы, агент
подбирает режим, профиль, материал и настройки, применяет их в слайсере и сохраняет пару G-code и 3MF.

Агент работает внутри плагина: окно чата — клиент OpenAI-совместимого API (`/chat/completions` с
`tools`) и хост MCP. Инструменты слайсера отдаёт встроенный MCP-сервер Brim, пользователь может
подключить свои MCP-серверы. Backend не нужен, если LLM даёт OpenAI-совместимый API; для Claude по
подписке есть прокси в `backend/`. Решения принимает модель.

## Установка

1. Соберите архив: `python3 plugin/build.py` (результат: `plugin/dist/Brim-<версия>.zip`).
2. В слайсере: Справка → Показать папку конфигурации, откройте `plugins`.
   Обычно это `%APPDATA%\steslicer\7.x\plugins`.
3. Распакуйте архив так, чтобы получилось `plugins\Brim\plugin.json`.
4. Перезапустите STE Slicer.
5. В меню появится пункт «Brim» → «Открыть чат».

## Настройка

Откройте «Brim» → «Настройки» или кнопку с шестерёнкой в окне чата.

| Поле | Значение |
|---|---|
| URL LLM | Адрес OpenAI-совместимого API до `/chat/completions`, например `https://host/v1` |
| Модель | Имя модели |
| Ключ доступа | Необязателен. Хранится в настройках слайсера, в журналы и переписку не попадает. Пустое поле оставляет сохранённый ключ |
| Язык, тема | RU или EN, тёмная или светлая |
| MCP-серверы | Brim встроен и всегда включён. Свои: имя (латиница), URL Streamable HTTP, один заголовок вида `Authorization: Bearer …`. Сервер можно выключить или удалить |

«Проверить соединение» запрашивает `GET {URL LLM}/models` и список инструментов всех серверов.

Claude по подписке: запустите backend (`LLM=true docker buildx bake && docker compose up` в корне),
URL LLM — `http://<адрес>:8000/v1`, модель — `sonnet`, ключ — OAuth-токен из `claude setup-token`.

## Как пользоваться

- Каждый чат — отдельный проект: папка `chats/<id>/` рядом с кешем плагина с историей
  (`chat.json`), сценой (`scene.3mf`), вложениями (`files/`) и результатом (`output/`). При
  переключении текущая сцена сохраняется, открывается сцена выбранного чата. Новый чат начинается с
  пустой сцены; «Новый из текущей сцены» переносит открытую сцену. Первое сообщение без открытого
  чата создаёт чат с текущей сценой. Если агент работает, плагин предлагает дождаться или остановить.
- Состояние сохранения («Есть изменения», «Сохраняем…», «Сохранено», «Не удалось сохранить») видно в
  шапке. При перезапуске открывается последний активный чат.
- Режим **С подтверждением**: перед каждым изменением проекта, слайсингом и вызовом внешнего
  инструмента (кроме помеченных только для чтения) появляется карточка «Применить / Отклонить».
  Текст в поле ввода уходит агенту комментарием к отказу. Режим **Авто**: агент действует сам, но
  карточка всё равно появляется, если значение настройки выходит за допустимые или рекомендуемые
  границы слайсера или меняется больше чем вдвое (например, стол 40 → 500 °C), а также для внешних
  инструментов, которые сервер пометил как разрушающие.
- Вопросы агента показаны карточкой; варианты ответа вставляются в поле ввода. Пока вопрос открыт,
  отправленное сообщение считается ответом. Открытый вопрос переживает переключение чата и перезапуск.
- Вложения (JPG, PNG, STL, OBJ, 3MF) копируются в папку чата. Картинки модель видит сразу, модель
  попадает в сцену, когда агент её импортирует.
- Вызовы инструментов и их исход видны в ленте; подряд выполненные вызовы свёрнуты в «Действия агента».
- «Остановить» прерывает ход. Уже применённое не откатывается.
- После слайсинга в ленте появляется карточка: время печати, расход материала, пути к файлам и кнопка
  «Открыть папку».

## Локальный MCP

Плагин слушает только `127.0.0.1`. Адрес и токен записываются в `<папка данных>\brim\mcp.json`
(`Resources.getDataStoragePath()`, обычно `%APPDATA%\steslicer\7.x`).

```
POST http://127.0.0.1:<порт>/mcp
Authorization: Bearer <токен из mcp.json>
```

Поддерживаются `initialize`, `tools/list`, `tools/call`. Запросы с заголовком `Origin` и чужим `Host`
отклоняются. Тот же диспетчер использует встроенный агент. Внешним клиентам подтверждения не
показываются: доступ ограничен loopback и токеном.

## Устройство

```
Brim/
  plugin.json, __init__.py, BrimExtension.py   точка входа и меню
  composition.py                               сборка зависимостей
  settings.py                                  настройки и MCP-серверы в Preferences слайсера
  agent/                                       цикл агента, клиент LLM, клиент и хаб MCP, ask_user, подтверждения
  protocol/                                    диспетчер и HTTP-сервер MCP, tools.json
  execution/                                   исполнитель инструментов, проверка операций, геометрия
  slicer/                                      адаптеры STE Slicer; классы UM и steslicer импортирует только host.py
  chat/                                        состояние чата, лента и презентер без Qt
  workspace/                                   папки чатов, сохранение и открытие сцены
  ui/                                          контроллер PyQt5 и QML-окно
```

Пока агент работает, над полем ввода видны фаза, номер шага и секундомер; через 60 с размышлений
модели появляется подсказка с кнопкой «Остановить».

Ход агента выполняется фоновым потоком: системный промпт с контекстом сцены, история чата и
инструменты всех серверов. Контекст несёт снимок сцены и текущие значения всех включённых настроек
(`slicer/settings_digest.py`); дамп кешируется до изменения стека настроек. Перед исполнением
инструмента в историю пишется отметка `interrupted`: если слайсер упадёт посреди вызова, после
перезапуска модель увидит неизвестный исход, а не повторит изменение.

Потоки: в главном потоке Qt выполняются только обращения к слайсеру через `app.callLater`
(`slicer/main_thread.py`), сеть и файлы идут в фоновых потоках. Геометрия анализируется вне главного
потока по снимку сетки.

## Разработка

```
cd plugin
PYTHONPATH=. python3 -B -m unittest discover -s tests -t .
python3 build.py
```

Код плагина должен работать на Python 3.5: без f-строк, аннотаций переменных и `async`. Тест
`test_python35_syntax` ловит самые частые нарушения, полную проверку даёт запуск в Docker
`python:3.5` и на встроенном Python слайсера. Импорты PyQt5 и `UM`/`steslicer` разрешены только в
`slicer/host.py`, `ui/controller.py`, `BrimExtension.py` и `composition.py`.

## Логи и удаление

Логи слайсера: `stderr.log` и `*.log` в папке конфигурации. Плагин пишет через `UM.Logger`.
Для обновления замените папку `plugins\Brim` и перезапустите слайсер. Для удаления удалите её, а при
желании и `<данные>\brim` вместе с чатами и `mcp.json`.

## Что проверить на Windows

1. Есть ли во встроенном Python `http.server`, `socketserver`, `ssl` (для `https://` LLM), `hmac`,
   `queue`; доверяет ли `ssl` сертификату LLM организаторов.
2. Создаёт ли `createQmlComponent` окно с новыми карточками (вопрос, подтверждение, MCP-серверы).
3. Полный ход: вопрос → ответ → изменение настроек с подтверждением → слайсинг → файлы в `output/`.
4. Режим «Авто»: безопасное изменение без карточки, выход за границы — с карточкой.
5. Переключение чатов во время открытого вопроса и после перезапуска слайсера.
6. Внешний MCP-сервер в настройках, например `@modelcontextprotocol/server-everything` в режиме
   Streamable HTTP.
7. `render_scene`: размер снимка и принимает ли его модель организаторов.
