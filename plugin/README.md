# Плагин Brim для STE Slicer

Плагин добавляет в STE Slicer окно чата. Пользователь описывает задачу и прикладывает файлы, агент на
backend подбирает режим, профиль, материал и настройки, а плагин выполняет эти команды в слайсере и
сохраняет пару G-code и 3MF.

Плагин делает технические операции: показывает чат, держит соединение с backend, отдаёт агенту состояние
сцены, исполняет инструменты и передаёт результаты. Решения принимает агент.

## Статус проверок

| Что | Статус |
|---|---|
| Транспорт, диспетчер, исполнение, журнал вызовов, передача файлов, чат-логика, локальный MCP, упаковка | macOS Python 3.14: 123 теста прошли; Python 3.5.10 (Docker): 122 прошли, один пропущен (проверка через AST нового Python). Без слайсера |
| Плагинный транспорт и чат с настоящим backend и PostgreSQL (Compose), LLM скриптовый | Проверено 2026-10-23 сценарием `tests/integration/run_real_backend.py`: регистрация, вложение, вопрос агента, карточка подтверждения, `apply_changes`, `slice`, оба файла на backend с совпавшим SHA-256, история после перезагрузки. Слайсер при этом заглушка, платная LLM не использовалась |
| Рендер QML | Загружается и отрисовывается в Qt 6 offscreen (темы, настройки); Qt 5 слайсера не проверялся |
| Загрузка в STE Slicer, чтение принтера, операции со сценой, слайсинг, экспорт, снимок сцены | **Не проверено**: нет доступа к STE Slicer 7.10.12, нужен стенд на Windows |

Обращения к API слайсера написаны по описанию организаторов и устройству Cura 3.6. Они не запускались.
Что именно проверить на стенде, перечислено в разделе «Что проверить на Windows».

## Установка

1. Соберите архив: `python3 plugin/build.py` (результат: `plugin/dist/Brim-<версия>.zip`).
2. В слайсере: Справка → Показать папку конфигурации, откройте `plugins`.
   Обычно это `%APPDATA%\steslicer\7.x\plugins`.
3. Распакуйте архив так, чтобы получилась папка `plugins\Brim\plugin.json`.
4. Перезапустите STE Slicer.
5. В меню появится пункт «Brim» → «Открыть чат».

## Настройка

Откройте «Brim» → «Настройки соединения» или кнопку «Настройки» в окне чата.

| Поле | Значение |
|---|---|
| Адрес backend | По умолчанию `http://localhost:8000`. Если Compose запущен вне Windows-виртуалки, укажите адрес, доступный из неё |
| URL LLM | Адрес OpenAI-совместимого API, выданный организаторами |
| Модель | Имя модели |
| Ключ доступа | Хранится в настройках приложения слайсера, в журналы и переписку не попадает. Пустое поле оставляет сохранённый ключ |
| Язык, тема | RU или EN, тёмная или светлая |

При первом подключении плагин регистрирует экземпляр слайсера на backend и сохраняет полученный токен.
Если backend сбросил базу и токен перестал приниматься, плагин регистрируется заново сам. Смена адреса
backend сбрасывает токен.

После перезапуска backend ключ LLM нужно отправить заново: плагин делает это при подключении.

Claude по подписке вместо OpenAI-совместимого API: «URL LLM» — `claude-agent`, «Модель» — `sonnet`
или полный ID модели, «Ключ доступа» — OAuth-токен из `claude setup-token`. Backend должен быть
собран с `LLM=true docker buildx bake`, иначе агент ответит ошибкой модели.

## Как пользоваться

- Новый диалог создаётся кнопкой в списке слева, при первом сообщении он создаётся автоматически.
  Каждый диалог — отдельный проект: при переключении текущая сцена сохраняется в 3MF, открывается
  сцена выбранного диалога. Новый диалог начинается с пустой сцены; «Новый из текущей сцены»
  переносит открытую сцену в новый диалог. Пока идёт переключение, правки агента отклоняются.
  Если агент работает, плагин предлагает дождаться или остановить задачу.
- Состояние сохранения («Есть изменения», «Сохраняем…», «Сохранено», «Не удалось сохранить»)
  видно в шапке. Проекты лежат в `workspaces/` рядом с кешем плагина; при перезапуске
  открывается последний активный проект.
- Режим **Авто**: агент вносит изменения сам. Режим **С подтверждением**: перед пакетом изменений
  агент показывает карточку с действиями и ждёт «Применить», «Отклонить» или «Уточнить».
  Для уточнения напишите текст в поле ввода и нажмите «Уточнить». Исходный режим нового диалога: с подтверждением.
- Прикрепление файла (JPG, PNG, STL, OBJ, 3MF) загружает его в диалог. В сцену он попадает только когда
  агент вызовет импорт.
- Вопросы агента показаны карточкой, ответ вводится в поле сообщения.
- Вызовы инструментов, их исход и ошибки показываются в ленте; подряд выполненные вызовы свёрнуты
  в блок «Действия агента». Этап работы виден в шапке, прогресс — под лентой.
- «Остановить» прекращает запуск и оставшуюся очередь изменений. Уже применённое не откатывается.
- После слайсинга в ленте появляется карточка: время печати, расход материала и кнопки сохранения
  G-code и 3MF из backend.
- Закрытие окна только скрывает его, текущее выполнение продолжается.

## Локальный MCP

Плагин слушает только `127.0.0.1`. Адрес и токен записываются в `<папка данных>\brim\mcp.json`
(`Resources.getDataStoragePath()`, обычно `%APPDATA%\steslicer\7.x`).

```
POST http://127.0.0.1:<порт>/mcp
Authorization: Bearer <токен из mcp.json>
```

Поддерживаются `initialize`, `tools/list`, `tools/call`. Запросы с заголовком `Origin` и чужим `Host`
отклоняются. Читающие инструменты работают сразу. Изменяющие (`apply_changes`, `slice`) выполняются только
для вызова, разрешённого backend: в `params._meta.call_id` нужен идентификатор вызова, который backend
прислал по WebSocket, а инструмент и аргументы должны совпасть с ним. Иначе возвращается
`execution_not_authorized`, режим подтверждений обойти нельзя.

Тот же диспетчер обслуживает `mcp_request` от backend по WebSocket. Это собственный мост, а не
стандартный транспорт MCP.

## Устройство

```
Brim/
  plugin.json, __init__.py, BrimExtension.py   точка входа и меню
  composition.py                               сборка зависимостей
  settings.py                                  настройки в Preferences слайсера
  protocol/                                    кадры, WebSocket, HTTP backend, MCP, авторизация, tools.json
  execution/                                   исполнитель инструментов, журнал, геометрия, файлы
  slicer/                                      адаптеры STE Slicer; классы UM и steslicer импортирует только host.py
  chat/                                        состояние чата и презентер без Qt
  ui/                                          контроллер PyQt5 и QML-окно
```

`protocol/tools.json` скопирован из `backend/src/app/domain/tools.json` без изменений, тест проверяет
совпадение. Контракт: `work/protocol-contract.md`, версия `2`.

Снимок сцены несёт текущие значения всех включённых настроек (`slicer/settings_digest.py`). Backend
кладёт их в контекст каждого хода агента; дамп кешируется до изменения стека настроек.

Потоки: в главном потоке Qt выполняются только обращения к слайсеру через `app.callLater`
(`slicer/main_thread.py`), сеть и файлы идут в фоновых потоках, снимки состояния объединяются
с задержкой 0,3 с. Геометрия анализируется вне главного потока по снимку сетки.

Надёжность: журнал вызовов хранится в `<данные>\brim\ledger.json`. Повторный `call_id` возвращает
сохранённый результат, тот же ID с другим содержимым отклоняется (`call_id_conflict`), вызов, прерванный
перезапуском, получает `outcome_unknown` и не повторяется. Устаревшая пара `scene_epoch` / `scene_version` даёт `stale_scene`
без изменений. При ошибке пакета выполнение останавливается, возвращается список уже применённого.
Файлы результата передаются по 1 МиБ с проверкой SHA-256 и подтверждения backend для обоих файлов;
при сетевой ошибке повторяется только загрузка. Переподключение идёт с растущей задержкой до 30 с и
сверяет незавершённые вызовы.

## Разработка

```
cd plugin
PYTHONPATH=. python3 -B -m unittest discover -s tests -t .
python3 build.py
```

Сквозной прогон с настоящим backend (нужен Docker; перед этим `COMPOSE_PROJECT_NAME=brim docker buildx bake && docker compose up -d` в корне):

```
cd plugin
PYTHONPATH=. python3 -B tests/integration/run_real_backend.py
```

Скрипт поднимает локальный OpenAI-совместимый сервер со сценарием; backend обращается к нему по `host.docker.internal` (меняется переменной `BRIM_LLM_HOST`, адрес backend — `BRIM_BACKEND`).

Код плагина должен работать на Python 3.5: без f-строк, аннотаций переменных и `async`. Тест
`test_python35_syntax` ловит самые частые нарушения, полную проверку даёт запуск на встроенном Python
слайсера. Импорты PyQt5 и `UM`/`steslicer` разрешены только в `slicer/host.py`, `ui/controller.py`,
`BrimExtension.py` и `composition.py`.

## Логи и удаление

Логи слайсера: `stderr.log` и `*.log` в папке конфигурации. Плагин пишет через `UM.Logger`.
Для обновления замените папку `plugins\Brim` и перезапустите слайсер. Для удаления удалите её, а при
желании и `<данные>\brim` вместе с журналом, кэшем файлов и `mcp.json`.

## Что проверить на Windows

1. Все ли модули стандартной библиотеки (`http.server`, `socketserver`, `ssl`, `hmac`, `queue`) есть во
   встроенном Python; какие версии Python, Qt и PyQt в дистрибутиве; доступны ли QtQuick 2.7 и
   QtQuick.Dialogs 1.2.
2. Загружается ли расширение, создаёт ли `createQmlComponent` окно, срабатывают ли `engineCreatedSignal`
   и привязка к главному окну.
3. Имена в API слайсера: `Preferences`, `getMachineManager()` и его свойства, `getQualityManager()`,
   `getMaterialManager()`, `getPrintInformation()`, `getWorkspaceFileHandler()`, сигнал `fileCompleted`,
   ключ `printing_mode` и значения `classic`, `cylindrical`, `cylindrical_full`.
4. Перевод координат на асимметричной модели: позиция, поворот, масштаб по трём осям.
5. Асинхронный импорт, расстановка, копирование, открытие 3MF с диалогом проекта.
6. Слайсинг в каждом из трёх режимов, запись G-code и 3MF штатными писателями, повторное открытие 3MF.
7. Автослайсинг после пакета возвращается в прежнее состояние.
8. Снимок сцены (`Snapshot.snapshot`): размер и содержимое изображения.
9. Тот же сквозной прогон, но с настоящим слайсером вместо заглушки и настоящей LLM.

## Изменения контракта 2

Обновление требует backend с контрактом 2 и миграцией эпох сцен. История и файлы сохраняются.
После рестарта слайсера новая эпоха отменяет актуальность прежних подтверждений. После рестарта
backend конфигурация LLM передаётся автоматически; выполнение ждёт сцену и согласование журнала.

Открытие диалога восстанавливает ожидающий вопрос, подтверждение, запуск и файлы. Подтверждать
можно только текущий пакет. Обычное сообщение агента также допускает текстовый ответ пользователя.

Просроченные задания Qt, которые ещё не начались, не выполняются позже. Неопределённый исход
начатого изменения требует проверки пользователем. Отмена не запускает оставшийся слайсинг и
останавливает следующие этапы экспорта и загрузки. Карточка файлов появляется после завершения
запуска на backend.

Писатель 3MF получает узлы сцены. Плагин проверяет целостность ZIP, геометрию и настройки проекта;
повторное открытие в выданном STE Slicer остаётся обязательной проверкой стенда.
