## Причина найдена, 2026-10-23, Windows 10 (192.168.1.190), STE Slicer 7.10.12, Qt 5.10.0

- Воспроизведено на Windows без Wine: окно «Brim (Не отвечает)», 100% одного ядра, память 738 МБ → 1,3 ГБ. Версия из main и ветки ведут себя одинаково.
- py-spy record 15 с, 750 сэмплов: все на главном потоке в `QtApplication.exec_`, Python-кода сверху нет. Значит, крутится QML/раскладка.
- Дамп реального `view`: 22 записи (сообщения, 3 вопроса, 3 подтверждения, 3 упавших `apply_changes`).
- Удаление `onContentHeightChanged: if (followEnd) positionViewAtEnd()` из Chat.qml: окно открылось с полной историей, CPU 0%, ~270 МБ, но не внизу ленты.
- Локальный стенд: Docker python:3.7 + PyQt5 5.10.1, `QT_QUICK_BACKEND=software`, реальный дамп view. main: 0 тиков цикла событий за 20 с (зависание). Логи делегатов: 2020 созданий и 2017 уничтожений за 5 с, записи 11–20 пересоздаются ~200 раз; высоты растут после создания (подтверждение 45→182, вопрос 66→311).
- Исправление: `cacheBuffer: 1000000`, ограниченная прокрутка вниз (таймер, до 20 повторов). Стенд: 21 создание, 0 уничтожений, точный contentHeight 3314, низ ленты на последней записи, новое сообщение тоже прокручивается.
- `ToolRow.qml:32` — это `anchors.verticalCenter: parent.verticalCenter` при уничтожении делегата; защищено проверкой parent. На стенде предупреждения исчезли.
- Windows с исправлением: окно открылось внизу истории, CPU 0%, 272 МБ, предупреждений QML нет.
