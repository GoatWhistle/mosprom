# Агент работает в плагине: клиент OpenAI-совместимого API и хост MCP

Заменяет [ADR 0001](0001-postgres-single-process-agent.md). Агентский цикл переехал из backend в
плагин STE Slicer. Плагин сам вызывает `POST {llm_url}/chat/completions` с `tools`, исполняет вызовы
инструментов и хранит историю чата и файлы в папке чата. Backend остался только для Claude по
подписке: stateless `POST /v1/chat/completions` переводит запрос в Claude Agent SDK.

## Рассмотренные варианты

- **Агент в backend, плагин исполняет команды по WebSocket (ADR 0001):** отклонено — жюри с LLM
  организаторов пришлось бы поднимать Docker и PostgreSQL ради одного чата; протокол с ledger,
  эпохами сцены и чанковой загрузкой файлов был самой сложной и наименее проверенной частью.
- **Официальные SDK (OpenAI, MCP) внутри плагина:** отклонено — оба требуют Python 3.8–3.10+, а
  встроенный Python слайсера — 3.5. Клиент `chat/completions` и Streamable HTTP MCP написаны на `urllib`.
- **Отдельный процесс-агент рядом со слайсером:** отклонено — ещё один исполняемый файл в поставке
  и тот же вопрос версии Python без выигрыша для жюри.

## Следствия

- Сдаётся zip плагина; для LLM организаторов Docker не нужен. Compose нужен только для Claude.
- Встроенный MCP-сервер Brim всегда включён; пользователь добавляет свои серверы по HTTP. Инструменты
  внешних серверов модель видит как `<сервер>__<инструмент>`.
- `ask_user` — встроенный инструмент цикла, а не MCP: он ставит ход на паузу до ответа пользователя.
- Подтверждение изменений — локальная карточка плагина. Режим «Авто» всё равно спрашивает о
  рискованных изменениях настроек.
- Нет базы данных: история — `chat.json`, сцена — `scene.3mf`, результат — `output/` в папке чата.
  Переживает перезапуск слайсера, но не переносится между машинами.
- Claude через эмуляцию медленнее нативного tool use: каждый шаг запускает CLI (около 8 с в замере
  2026-10-23), transcript отправляется целиком.
