# Скиллы агента, чтение документов и справочники в плагине

Дополняет [ADR 0002](0002-plugin-agent-openai-mcp-host.md). Эксперты кейса описали два сценария:
настроить печать новичку по модели и разобрать дефекты по фото отпечатка. К тестовым моделям
приложены ТЗ в DOCX. Для этого во встроенный MCP-сервер Brim добавлены инструменты документов, справочников, расчётов
и калибровки, а также каталог скиллов, который агент выбирает сам. Генерация STL и журнал
создают локальные файлы; применение настроек остаётся отдельной операцией.

## Решение

- **Скиллы** — файлы `Brim/skills/<имя>/SKILL.md`: заголовки RU/EN, описание, когда применять, и
  инструкция. Каталог из имён и описаний идёт в системный промпт каждого хода. Агент загружает
  нужную инструкцию инструментом `load_skill`, текст остаётся в истории чата. Пользователь может
  закрепить скилл в чипе рядом со скрепкой; выбор хранится в `chat.json`, и тогда инструкция
  попадает в промпт сразу. Скиллы: «Новичок», «Инженер», «Материал», «Дефекты».
- **`read_document`** читает вложения DOCX, XLSX, CSV/TSV, TXT, MD, JSON и PDF средствами стандартной
  библиотеки Python 3.5 (`zipfile`, `xml.etree`, `csv`, `zlib`). Таблицы отдаются в Markdown,
  длинный текст — страницами по `next_start`. Читаются только файлы из папки текущего чата.
- **`lookup_defect`** ищет дефект по описанию на русском или английском в `knowledge/defects.json`
  и возвращает причины, ключи настроек с направлением и типичным шагом и текущие значения из слайсера.
  Ключ, которого нет в слайсере, попадает в `unknown_keys`, а не в рекомендации.
- **`match_materials`** сопоставляет материалы слайсера с семействами полимеров из
  `knowledge/materials.json` и проверяет требования: температура, плотность, гибкость,
  химстойкость, влагопоглощение, трение, проводимость наполнителя, ползучесть.
- **`calculate`** — расчёты, которых нет в слайсере: изгиб зуба по Льюису, кручение вала,
  центробежные напряжения, масса, тепловое расширение, компенсация отверстий.
- **`generate_calibration_model`** пишет в папку чата STL тестовой детали. По умолчанию для новичка —
  калибровочная фигурка `calibration_figure`: одна неизменная деталь с зонами под первый слой,
  нависания, мост, паутину, отверстия, тонкую стенку, мелкие слои и верхнюю поверхность. Отдельные
  детали (кубик, нависания, мосты, башни на паутину, отверстия) уточняют одну зону.
- **`calibration_journal`** ведёт журнал попыток калибровки в папке чата: наблюдения по зонам,
  запланированные правки, вывод попытки, фото и снимок настроек. Сравнивает последнюю попытку
  с предыдущей той же геометрии. Настройки не меняет.

## Рассмотренные варианты

- **Только ручной выбор режима:** отклонено — пользователь не знает, какой режим нужен; агент
  видит задачу и выбирает сам. Ручное закрепление оставлено для демонстрации и предсказуемости.
- **Все инструкции в одном системном промпте:** отклонено — промпт растёт с каждым сценарием,
  а инструкции разных скиллов противоречат друг другу (подробно объяснять / не задавать вопросов).
- **Библиотеки python-docx, openpyxl, pdfminer:** отклонено — встроенный Python слайсера 3.5,
  современные версии библиотек его не поддерживают, а поставка — один zip без зависимостей.

## Следствия

- Справочные числа о материалах — типовые значения для ненаполненных марок, а не свойства
  конкретной нити. Агент обязан так их и называть; точные значения — по TDS производителя.
- Шаги правок в справочнике дефектов — стартовые приращения, а не измеренные оптимумы.
- PDF без текстового слоя (скан, картинки слайдов) и зашифрованный PDF дают честную ошибку.
- Расчёты — инженерные оценки с перечисленными допущениями, а не проверка прочности детали.
