# План валидации

План зафиксирован при обновлении документации 24.10.2026 для следующих прогонов. Предыдущие
результаты описаны в [доказательствах](evidence.md) и не объявляются полученными по этому плану.
Ниже наши условия приёмки; организаторы не публиковали численные веса, допуски к эталонам и пороги.

## Фиксация условий

Перед прогоном записать Git SHA, версию Brim и STE, ОС, принтер и профиль, LLM и базовый URL,
режим подтверждений, исходные файлы с SHA-256 и время начала. Ключи не включать в протокол.
Для каждого повторения — отдельный чат; указать причину повтора и сохранить неудачную попытку.
Изменение кода, промпта или профиля создаёт новую серию, а не заменяет неудобный результат старой.

Живые запросы LLM требуют отдельно выделенного доступа и запуска оператором. Автотесты используют
подставленные провайдеры и не тратят квоту. Изменение документации само по себе не запускает печать,
стенд или платные модели.

## Проверки и условия принятия

| Проверка | Выборка / процедура | Условие принятия | Что сохранить |
|---|---|---|---|
| Установка | Чистая конфигурация STE 7.10.12, ZIP текущей версии | Меню и обе оболочки открываются; настройки LLM сохраняются | SHA архива, лог, снимок меню |
| Чат и проекты | Два чата с различными моделями, повторное открытие после перезапуска | Каждому соответствует своя сцена и история; ошибку восстановления видно | Обе сцены, chat.json, снимки |
| Подтверждение | Принять, отклонить с комментарием; числовой риск в Авто на тестовой сцене | Отклонённое изменение не применяется, комментарий учтён; карточка риска видна | До/после, вызовы инструментов |
| Требования к инструментам | По одной контролируемой операции каждого kind на расходной сцене | Состояние и сохранённый проект отражают операцию; частичный отказ явный | Таблица операции → результат |
| Семь наборов | Один новый чат на каждый официальный набор, все файлы прочитаны | Для каждого комплект файлов; все отказы и нарушения ТЗ явно записаны | 3MF, G-code, Markdown, PNG, журнал попыток |
| Проверка артефактов | Каждый комплект | ZIP CRC, открытие 3MF, нужная модель, режим/материал/профиль/ориентация; просмотр траекторий и заголовков G-code | Протокол по каждому файлу и хеши |
| Переход 5D → 3D | В отдельной серии повторить три раза | Следующая classic-нарезка завершается; отсутствие успеха — открытый блокер | Логи движка и все попытки |
| Браузер | 375 и 1440 px, RU/EN, обе темы | Читаемые карточки и ошибки, без горизонтального скролла; вход, вопрос, подтверждение, результат | Снимки и перечень действий |
| LLM организаторов | Сначала один пример с картинкой/tools, затем семь наборов без зеркала | Решения и инструменты действительно исходят от неё; ошибки по каждому набору записаны | Обезличенный протокол API, чаты |
| Калибровка | Одна геометрия, минимум две физические попытки с фото A–D и измерениями | Журнал связан с настройками каждой печати; эксперт подтверждает или опровергает диагноз | Фото, настройки, измерения, журнал |

Для сценария с опасным числовым изменением используйте расходную сцену без запуска принтера;
после отказа проверьте, что значение сохранилось. Подтверждение риска не является разрешением
печатать заведомо неподходящую конфигурацию.

## Метрики для следующего сравнения

Сравнение с ручной работой: те же семь наборов, одинаковые принтер, материал и исходные условия.
Отдельно записать активное время оператора и полное время до проверенного комплекта, число вопросов,
повторов, перезапусков, незавершённых заданий и нарушенных требований. Для ручного участника
указать опыт; порядок задач чередовать. Порог «быстрее на X %» до пилота не установлен.
Публиковать значения по каждой задаче и медиану, не удалять неудачные прогоны.

Для дефектов нужен размеченный набор реальных фото с согласованным списком дефектов и оценкой
специалиста. Размер выборки и пороги фиксируются до начала такого исследования. Пока нет набора,
процент точности не публикуется. Для прочности и допусков нужен отдельный физический протокол.

## Воспроизведение локальных проверок

Команды из корня репозитория:

```bash
(cd plugin && PYTHONPATH=. python3 -B -m unittest discover -s tests -t .)
(cd backend && uv run ruff check . && uv run mypy . && uv run pytest tests/unit)
python3 plugin/build.py
python3 -m zipfile -t plugin/dist/Brim-0.5.2.zip
```

Тесты плагина проверяют агентский цикл, подтверждения, MCP, операции и проекты на тестовых
адаптерах. Backend проверяет преобразование сообщений, ошибки, зеркало и границы слоёв.
Для подтверждения реального Qt, 5D и писателей файлов нужен ручной маршрут
[демонстрации](for-jury.md). Проверка финального комплекта — в [сдаче](delivery.md).
