# Установка, запуск и проверки

Основная поставка — плагин Brim 0.5.2. Для прямого подключения к OpenAI-совместимой LLM нужен
STE Slicer и доступ к API. Backend, Docker и база данных для этого пути не требуются.
Без доступной LLM агент выдаёт ошибку; автономного офлайн-режима рекомендаций нет.

## Установка плагина

Проверенная среда стенда: Windows 10, STE Slicer 7.10.12, профиль Stereotech Hybrid 530 V5.2.4.
Код рассчитан на Python 3.5 и PyQt5 из слайсера, `plugin.json` указывает `api: 5`.
Совместимость с другими сборками STE требует проверки.

Из корня репозитория:

```bash
python3 plugin/build.py
```

1. Закройте STE Slicer. Сохраните копию установленного `Brim`, если обновляете плагин.
2. Распакуйте `plugin/dist/Brim-0.5.2.zip` в папку `plugins` конфигурации STE Slicer.
   Обычно это `%APPDATA%\steslicer\7.x\plugins`; путь можно узнать через
   «Справка → Показать папку конфигурации» до закрытия программы.
3. Проверьте итоговый путь `plugins\Brim\plugin.json` и запустите слайсер.
4. Выберите нужный принтер и откройте «Brim → Настройки». Укажите URL LLM, модель и ключ.
5. Нажмите «Проверить соединение», затем откройте чат через меню Brim.

Не устанавливайте дополнительные Python-пакеты в STE: плагин использует стандартную библиотеку
и модули, уже поставляемые слайсером. `plugin/build.py` упаковывает только каталог `Brim/`.

Для 5D нужна активированная поставка STE и доступный OpenSCAD. Рабочая папка запуска STE должна
совпадать с папкой его установки; обычный ярлык поставки подходит. Подробности ошибок —
в [устранении неполадок](troubleshooting.md).

## Подключение модели

| Поле | Прямое подключение | Claude через backend |
|---|---|---|
| URL | Выданный базовый URL OpenAI-совместимого API, обычно с `/v1` | `http://127.0.0.1:8000/v1` на той же машине |
| Модель | Имя модели провайдера | `opus`; backend принудительно выбирает её |
| Ключ | Ключ провайдера | OAuth-токен, полученный командой `claude setup-token` |

По данным проверки 24.10.2026 API организаторов принимает картинки и tool calls; весь комплект
из семи моделей прогонялся с Claude. Эти результаты не взаимозаменяемы.

## Необязательный backend через Docker

Нужны Docker с Buildx и Compose v2. Команды из корня; `.env` создавайте только при первом запуске,
чтобы не затереть существующие настройки:

```bash
cp -n .env.example .env
COMPOSE_PROJECT_NAME=brim TAG=latest LLM=true docker buildx bake
COMPOSE_PROJECT_NAME=brim TAG=latest docker compose up -d --wait
curl --fail http://127.0.0.1:8000/api/v1/health
```

Явное `COMPOSE_PROJECT_NAME=brim` даёт одинаковое имя образа в Bake и Compose.
Bake сам по себе не обязан читать `.env` как Compose; без явного имени можно собрать
`app-backend:latest`, когда Compose ожидает `brim-backend:latest`.

Ответ health подтверждает живость HTTP-процесса, но не авторизацию Claude. Образ без `LLM=true`
работает для health и отвечает 503 при попытке генерации. Первая сборка требует сети для образов
и зависимостей. Для реального вызова Claude нужен действующий доступ; такая проверка не входит
в обычные автоматические тесты.

Порт Compose опубликован только на `127.0.0.1`. На другой машине или VM этот адрес означает саму
VM. Для доступа используйте отдельно настроенный туннель или публикацию порта в доверенную сеть.
Готового универсального сетевого конфига для VM в репозитории нет.

Журнал и остановка:

```bash
COMPOSE_PROJECT_NAME=brim docker compose logs --tail=100 backend
COMPOSE_PROJECT_NAME=brim docker compose down
```

## Backend без Docker

Нужны Python 3.12+ и uv. Из корня:

```bash
(cd backend && uv sync --locked)
(cd backend && uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000)
```

`uv sync` устанавливает группы `dev` и `llm` по умолчанию. Прямой запуск не загружает корневой
`.env` автоматически: передайте необходимые переменные через окружение процесса.

## Переменные

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `COMPOSE_PROJECT_NAME` | `app` в Compose/Bake; `brim` в примере `.env` | Префикс сервиса и имени образа |
| `TAG` | `latest` | Тег образа |
| `BACKEND_PORT` | `8000` | Порт на хосте Compose |
| `LLM` | `false` в Bake | Добавить Claude Agent SDK при сборке; используйте `true` для генерации |
| `LLM_TIMEOUT_SECONDS` | `120` | Таймаут вызова Claude; положительное число |
| `MIRROR_BASE_URL` | Пусто в приложении | Базовый URL необязательного второго провайдера |
| `MIRROR_API_KEY` | Пусто | Его ключ |
| `MIRROR_MODEL` | Пусто | Его модель |

В `.env.example` заданы URL и имя модели зеркала, но ключ пустой, поэтому зеркало выключено.
Оно включается только при заполнении всех трёх `MIRROR_*`. Тогда второму провайдеру передаются
вся история, изображения и описания инструментов из запроса. Его ответ отбрасывается;
пользователь продолжает работать с Claude. Зеркало может расходовать квоту второго провайдера.

## Автоматические проверки

Все команды ниже запускаются из корня. Подстановки LLM и слайсера используются только в тестах.

```bash
(cd plugin && PYTHONPATH=. python3 -B -m unittest discover -s tests -t .)
(cd backend && uv run ruff check .)
(cd backend && uv run mypy .)
(cd backend && uv run pytest tests/unit)
```

Группа `llm` нужна для импорта типов SDK; сетевые вызовы в тестах подменены. Необязательные проверки против исходников
Uranium пропускаются без соответствующего checkout; это не подтверждение работы внутри STE.
Группы `backend/tests/integration` сейчас нет.
