# Результаты и доказательства

Дата сводки: 24.10.2026. Исходники: `23f7329`, версия пакета 0.5.2. Ниже отдельно указаны
прошлые ручные прогоны, локальные проверки и ещё не выполненные измерения.

## Происхождение результатов

Ручной стенд: Windows 10 VM, STE Slicer 7.10.12. Модели — семь наборов STL + DOCX + JPG,
предоставленных организаторами. В ходе проверки использовались версии Brim 0.4.0, 0.4.1,
затем отдельные функции 0.5.0–0.5.2. Для семи деталей: новый чат на модель, скилл «Инженер»,
режим «Авто», Claude через backend; журнал этого прогона указывает `opus`.

Сводка перенесена из датированного журнала команды. В текущем checkout нет самих экспортов:
они сохранены на стенде в `Desktop/results/<модель>/`.
Поэтому эта страница даёт проверяемые идентификаторы и метод, но не заменяет просмотр файлов.
Число попыток было больше семи: пыльник прошёл с третьей попытки, шестерня и фигурка прогнаны заново.
Эти данные нельзя называть «семь успешных первых попыток» или статистикой надёжности.

## Автоматические проверки

В журнале слияния перед текущим обновлением документации: 155 успешных тестов плагина,
2 необязательных теста Uranium пропущены. Проверки выполнялись на современных Python,
не в Python 3.5 поставки STE. В отдельных сессиях указаны Python 3.13 и 3.14; результаты нельзя
складывать в одну выборку. Статическая проверка совместимости `vermin` для добавленной калибровки
сообщала минимум Python 3.5.

Актуальные команды находятся в [инструкции запуска](running.md). Успех unit-тестов не доказывает отсутствие ошибок
в Qt, писателях файлов и движках STE. При обновлении документации 24.10.2026 проверки повторены на macOS, исходники `23f7329`:

| Команда | Среда | Результат |
|---|---|---|
| `PYTHONPATH=. python3 -B -m unittest discover -s tests -t .` из plugin/ | Python 3.14.2 | 155 тестов всего: 153 успешных, 2 пропущены (нет checkout Uranium) |
| `uv run --locked ruff check .` из backend/ | Окружение uv | Без ошибок |
| `uv run --locked mypy .` из backend/ | Python 3.14.0, 37 файлов | Без ошибок |
| `uv run --locked pytest tests/unit` из backend/ | Python 3.14.0 | 67 успешных |

Установочный ZIP 0.5.2 собран командой `python3 plugin/build.py` и проверен
`python3 -m zipfile -t plugin/dist/Brim-0.5.2.zip`: ошибок CRC нет. Конфигурации Bake и Compose
с явным `COMPOSE_PROJECT_NAME=brim TAG=latest` указывают на один образ `brim-backend:latest`;
это проверка конфигурации, без пересборки и запуска контейнера.

Платные запросы и реальный STE в этом повторе не запускались. Старую запись «155 прошли,
2 пропущены» не следует складывать: свежий unittest-вывод включает пропуски в общее число.

## Что результаты не доказывают

Не измерены качество физической детали, выполнение всех условий DOCX, превосходство над ручной
настройкой, надёжность на иных моделях, точность диагностики дефектов и стоимость сценария.
Эталонные 3MF недоступны участникам. Исправления ошибок между попытками означают, что протокол
выше является отчётом о разработке и повторных прогонах, а не заранее зафиксированным экспериментом.
