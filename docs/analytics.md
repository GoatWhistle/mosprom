# Аналитика: аудитория, аналоги, ценность

> Brim — чат-ассистент внутри STE Slicer для начинающего специалиста по FDM-печати: задача текстом,
> STL, фото и ТЗ на входе; настроенный проект 3MF, G-code и объяснение решений на выходе. Документ
> отвечает на критерии жюри 5.4.1–5.4.7 по порядку. Все цифры помечены статусом из
> [словаря доказательств](evidence.md#как-оценивается-каждое-утверждение); аналоги просмотрены
> 2026-10-24, ссылки — в конце.

**Читайте, если** вы оцениваете аналитику (5.4.7) или ищете ответ на вопрос «чем это лучше X» ·
**Связано:** [требования](../brief/requirements.md) · [доказательства](evidence.md) ·
[ограничения](limitations.md)

## Кто пользователь?

Основная аудитория задана кейсом и подтверждена экспертами на консультации 2026-10-23
([QA](../brief/QA.md#консультация-с-экспертами--2026-10-23)): «чат-бот, который помогает новичку».

| Сегмент | Кто это | Что делает с принтером | Что ему мешает сейчас |
|---|---|---|---|
| **А. Начинающий технолог** (основной) | Инженер или оператор на предприятии, в лаборатории, колледже, где стоит Stereotech; разбирается в своей детали, но не в слайсере | Печатает функциональные детали по ТЗ: шестерни, колёса, оси, пыльники | Не знает, какие из сотен параметров важны для его нагрузки, материала и режима 5D |
| **Б. Студент / преподаватель** | Учебный курс по аддитивным технологиям | Печатает учебные и демонстрационные модели, калибрует принтер | Нет наставника рядом; пробные печати съедают время занятия и пластик |
| **В. Опытный инженер** (вторичный) | Технолог, который умеет настраивать вручную | Готовит много разных деталей | Рутина: каждый раз заново прописывать профиль под материал и ТЗ |

Сегмент А — тот, для кого жюри проверяет семь моделей: в каждой задаче деталь описана инженерным
ТЗ (момент, температура, химия, допуски), а не настройками слайсера.

### Какие задачи и боли у новичка?

| # | Задача пользователя | Боль | Источник боли |
|---|---|---|---|
| Б1 | Понять, какие параметры трогать | В определении принтера STE Slicer **661 параметр** в 17 категориях | **Измерено:** подсчёт настроек не-категорий в `fdmprinter.def.json` дистрибутива |
| Б2 | Перевести ТЗ детали в настройки | ТЗ говорит «Tg ≥ 85 °C, 25 Н·м, щёлочь», слайсер — «wall_line_count», «infill_sparse_density» | Тексты ТЗ всех семи моделей, [MODELS.md](../brief/MODELS.md) |
| Б3 | Выбрать материал | Каталог Stereotech с десятками марок; свойства не видны в слайсере | Список материалов STE Slicer |
| Б4 | Выбрать режим 3D / 5D Spiral / 5D и ориентацию | 5D есть только у Stereotech; привычных туториалов по нему нет; неверный выбор зависает в нарезке | Наш прогон: B9, B20 в [журнале прогона](../work/jury-run-bugs.md) |
| Б5 | Не тратить материал на пробные печати | В открытой мастерской ~34 % пластика уходило в отходы; доля неудачных печатей по опросу — до 41 % | **Из источника:** исследование отходов FDM и опрос, см. ссылки [6], [7] |
| Б6 | Исправить дефект после печати | Нитки, капли, дыры в стенке, жирный первый слой: непонятно, какой параметр виноват | Эксперты на консультации; классификации отказов в [8] |
| Б7 | Не начинать заново при смене материала | Профиль под одну задачу не переносится на другую | Кейс, раздел 1, проблема 4 |
| Б8 | Доверять результату | Чат-бот «общего назначения» уверенно советует, но не видит слайсер и ошибается | Отзывы на форуме Prusa [9] |

## Какие есть аналоги?

Три класса: ИИ внутри потребительских слайсеров, внешние агенты над слайсером (MCP), и то, чем
новичок пользуется сейчас — ручная настройка, готовые профили и универсальный чат-бот в соседней вкладке.

| Аналог | Что делает | Модель доступа | Угроза |
|---|---|---|---|
| **Creality Print 7.2 AI Edition** [1] | ИИ-режим для новичков: рекомендации параметров, проверка и ремонт модели, анализ рисков печати, справочный ассистент | Бесплатно, бета; ассистент отвечает только по FDM-продуктам Creality | **A** — та же аудитория, но только принтеры Creality |
| **JusPrin (Obico)** [2] | Загрузить модель, описать цель — ИИ выбирает настройки и нарезает; помощь с неудачными печатями | Отдельное приложение на движке OrcaSlicer, Windows/macOS, open source | **A** — тот же сценарий, другой слайсер, без 5D |
| **SimplyPrint Cloud Slicer, Expert mode** [3] | Ассистент предлагает профиль и «короткий список» глобальных настроек под цель; ищет настройку | Облако, по тарифу и лимиту AI-запросов | **B** — только настройки, без сцены и ориентации |
| **Talk to AiSync (Ai Build)** [4] | Голос / текст → нарезка для промышленной крупноформатной печати; GPT-4 поверх движка Ai Build | Бета для отдельных партнёров (2023–2024), публичного релиза не нашли | **B** — промышленные роботы, не новичок |
| **Cura MCP Server (AuraFriday)** [5] | Плагин Cura 5.11+: внешний ИИ-клиент управляет слайсером на естественном языке | Проприетарная лицензия; нужен MCP-Link и свой ИИ-клиент | **A** — тот же механизм (MCP), но для опытного пользователя с внешним агентом |
| **OrcaSlicer MCP** [10] | MCP-сервер: модели, пресеты, нарезка в живом OrcaSlicer | Open source; клиент — внешний MCP-клиент (Claude Desktop и подобные) | **B** — инструмент для разработчика |
| **Bambu Studio** [11] | Авто-ориентация и авто-расстановка; ИИ-детекция «спагетти» в камере старших принтеров | Бесплатно; ИИ — в железе X1/P2S, не в слайсере | **B** — автоматизация шагов, без диалога и ТЗ |
| **Obico** [12] | ИИ-детекция отказа по камере во время печати | Free 10 ч/мес; платно ~$4–7/мес; self-hosted бесплатно | **B** — ловит брак, не настраивает |
| **Ручная настройка + готовые профили STE Slicer** | Профили качества и материалов Stereotech, рекомендованный режим Cura | Входит в слайсер | **S** — то, с чем реально сравнивают; требует опыта |
| **Универсальный чат-бот рядом** | Советы по параметрам и дефектам | Бесплатно / подписка | **A** — не видит сцену, не меняет настройки, ошибается в диагнозе [9] |

Ни у одного найденного аналога нет поддержки STE Slicer и 5D-режимов Stereotech: Creality, Bambu,
Orca и Cura строят траектории только в плоских слоях.

### Где аналоги сильнее нас

- **Зрелость и аудитория.** Creality, Bambu, Obico имеют миллионы пользователей и годы отладки.
  Brim проверен на одном стенде и семи моделях.
- **Детекция брака во время печати.** Obico и Bambu смотрят в камеру и ставят печать на паузу.
  Brim работает до печати и после неё по фото, к принтеру не подключён.
- **Скорость ответа.** Встроенные рекомендации Creality и SimplyPrint отвечают за секунды. Наш полный
  прогон одной модели через агента — 9–40 минут, большая часть — ход модели и нарезка (N1 в
  [журнале](../work/jury-run-bugs.md)).
- **Широта принтеров.** Brim сделан под STE Slicer; на другие слайсеры не переносится без нового
  адаптера сцены.

### Наше отличие в одном предложении

- **Против Creality AI / JusPrin:** Brim переводит инженерное ТЗ в настройки через таблицу требований
  с цитатами и расчёт прочности, и выбирает между 3D и двумя 5D-режимами — этого нет ни у кого.
- **Против Cura MCP / OrcaSlicer MCP:** у них MCP-сервер ждёт внешнего агента; у нас агент, MCP-хост и
  сервер внутри плагина, пользователь вводит только URL и ключ.
- **Против универсального чат-бота:** Brim видит реальную сцену и профиль числами, сам вносит изменения и
  показывает каждое; чат-бот только советует.
- **Против ручной настройки:** то же решение, что принял бы технолог, но с объяснением каждого
  параметра и сохранённой перепиской как документом.

## 5.4.7 Аналитика — итог

Аудитория — начинающий технолог (сегмент А), её задачи Б1–Б8 выше. Аналоги разобраны по трём
классам; где они сильнее — сказано. Ниже, по остальным критериям, — как Brim закрывает каждую боль
и чем это подтверждено.

## 5.4.2 Основная проблема: «сотни параметров, новичку трудно»

| Боль | Механизм Brim | Статус |
|---|---|---|
| Б1 661 параметр | Агент ищет настройку по смыслу (`search_settings`), меняет только нужные, остальное берёт из профиля Stereotech | **Наблюдалось:** 7 моделей, на модель 9–18 вызовов инструментов, 10–32 операции |
| Б2 ТЗ → настройки | Скилл «Инженер»: читает DOCX/PDF целиком, строит таблицу «требование — значение — цитата», затем меняет параметры | **Наблюдалось:** таблица требований в каждом из 7 чатов |
| Б4 3D/5D | Правила выбора режима: 5D — только для тел вращения, при >200 000 треугольников 5D запрещён; база 5D — по диаметру отверстия | **Наблюдалось:** режим совпал с подсказкой в имени папки у 6 из 6 моделей; фигурку (режим не указан) агент повёл в classic |
| Корректный G-code | Нарезка штатным движком STE Slicer, не генерация текста моделью | **Проверено вручную:** у 7 G-code заголовок режима = `printing_mode` 3MF, температура сопла = материалу, у 5D есть оси A/C |

Близость к эталонным 3MF жюри **не измерена**: эталоны у жюри.

## 5.4.6 Второстепенные проблемы

| Проблема кейса | Как закрыта | Статус |
|---|---|---|
| 1. Слайсер сложно освоить | Скилл «Новичок»: перед каждым изменением 2–3 предложения — что делает параметр, почему это значение, что будет при ошибке | **Код**; на стенде — в отдельном прогоне калибровки |
| 2. Пробные печати тратят материал | Прочность проверяется расчётом до печати (зуб шестерни по Льюису показал, что 25 Н·м не выдерживается, — пользователь получил риск до печати); калибровочная фигура одна вместо серии тестов; журнал попыток | **Наблюдалось** (шестерня, ось Krones); экономия материала **не измерена** |
| 3. Нет единой точки входа | Один чат: STL + фото + ТЗ → 3MF + G-code + скриншоты и выгрузка переписки | **Наблюдалось** на 7 моделях |
| 4. Смена материала — всё заново | Подбор материала по требованиям (`match_materials`, 16 семейств пластиков) и смена через тот же чат; каждый чат привязан к своему проекту, переключение чата восстанавливает проект | **Код**, частично на стенде |
| Наше: ответ ИИ не проверить | Каждое действие агента видно с аргументами; рискованные изменения (параметр меняется более чем вдвое) требуют подтверждения | **Наблюдалось:** карточка подтверждения 20 → 100 % заполнения у шестерни |
| Наше: дефект после печати | Скилл «Дефекты»: фото → дефект → параметры из справочника 15 типовых дефектов | **Код**; на реальных фото брака **не проверено** |

## 5.4.3 Эффект против затрат

**Затраты на внедрение.** Установка — распаковать папку плагина в каталог плагинов STE Slicer и
перезапустить; настройка — URL, ключ и модель LLM в окне настроек. Сервер, база данных и
Docker для сценария жюри не нужны.

**Эффект во времени** — честно:

| Что | Значение | Статус |
|---|---|---|
| Brim, шестерня: от создания чата до выгрузки 3MF + G-code | 9 мин | **Наблюдалось**, n=1, LLM Claude через прокси |
| Brim, фигурка, то же | 12 мин | **Наблюдалось**, n=1 |
| Brim, один ход модели | 1–3 мин | **Наблюдалось** (N1) |
| Ручная настройка той же детали новичком | — | **Не измерено** |
| Ручная настройка экспертом | — | **Не измерено** |

Прогоны жюри выполнены через Claude по подписке; LLM организаторов (`qwen3.8-flash`) проверен только
на одиночных запросах с картинкой и tools ([доказательства](evidence.md)). На нём время и качество
могут отличаться.

**Как измерить эффект (план, ещё не выполнен):** 3 участника без опыта STE Slicer, 3 модели из
набора жюри; каждый готовит одну деталь вручную с документацией и одну через Brim, порядок
чередуется. Метрики: время до валидного G-code, число параметров, изменённых не по ТЗ, число ошибок
режима 3D/5D, оценка эксперта по чек-листу ТЗ.

**Количественная ценность — ориентиры из источников, не наши замеры:** если в учебной или открытой
мастерской до трети пластика уходит в отходы [6], а доля неудачных печатей у новичков достигает
~41 % [7], то каждая отменённая пробная печать окупает время ассистента. Для фигурки (193 г, 74 ч на
штуку) одна лишняя пробная печать стоит больше 3 суток работы принтера.

**Сопровождаемость.** Код плагина разбит по слоям (агент, протокол MCP, исполнение на сцене, знания,
UI), модули кода до 250 строк (исключение — словарь строк интерфейса), 155 модульных тестов. Знания о материалах и дефектах — JSON, их правит
технолог без программиста.

## 5.4.4 Новаторские идеи — что не повторяет аналоги

1. **ТЗ → таблица требований с цитатами → настройки.** Аналоги принимают «цель» одной фразой; Brim
   читает инженерный документ и показывает, из какой строки ТЗ взялся каждый выбор.
2. **Инженерный расчёт до печати.** Изгиб зуба по Льюису, кручение вала, напряжения во вращающемся
   диске, масса, тепловое расширение, компенсация отверстий — формула видна в чате.
3. **Учёт специфики 5D.** Правила выбора между classic / cylindrical / cylindrical_full по
   геометрии (тело вращения, отверстие под оправку, число треугольников).
4. **Геометрия числами, картинка — дополнение.** Агент получает габариты, нависания, площади опоры
   по направлению — не угадывает по рендеру.
5. **Агент внутри плагина.** OpenAI-совместимый клиент и MCP-хост на Python 3.5 в процессе
   слайсера: работает с LLM организаторов без внешних серверов.
6. **Калибровочная фигура и журнал попыток** для новичка вместо набора тестовых моделей из интернета.

## 5.4.5 UI/UX — какие боли закрывает интерфейс

| Боль | Решение в интерфейсе |
|---|---|
| «Что сделал ИИ?» (Б8) | Каждый вызов инструмента — строка с названием, аргументами и итогом |

| «Ошибка — и непонятно что делать» | Без LLM чат показывает ошибку с названием недостающего (URL, ключ), а не выдуманный ответ |

## 5.4.1 Прототип

Заявленное и проверенное — в [карте требований](requirements-map.md) и
[журнале прогона](../work/jury-run-bugs.md): плагин 0.5.2 установлен в STE Slicer 7.10.12 на Windows
10, 7 моделей из набора организаторов прошли через чат до 3MF и G-code, все вызовы инструментов в
финальных чатах завершились успешно.
